# 🌕 MoonCrisis

Мини-игра «доставка грузов по Луне». SPA на React, бэкенд на Go, база — PostgreSQL.
Всё поднимается одной командой через Docker Compose.

## Что это за игра

Вы управляете базой на Луне с одним стартовым ровером. На карте 10×10 появляются
заказы с грузом. Нужно отправлять роверы за заказами, успевать в дедлайн,
не терять рейтинг и заработать максимум за 50 дней.

---

## Быстрый старт

Требуется: **Docker** и **Docker Compose**.

```bash
docker compose up --build
```

Открой в браузере: **http://localhost:3000**

Сервисы:

| Сервис    | Адрес            | Что это                          |
|-----------|------------------|----------------------------------|
| `db`      | —                | PostgreSQL 16 (внутри сети)      |
| `backend` | `:8080`          | Go API                           |
| `frontend`| **:3000**        | React SPA (nginx + прокси на API)|

### Важно про сброс базы

При первом старте миграции применяются автоматически из
`backend/migrations/001_init.sql`. Если схема уже применена (том `pgdata` есть),
изменения миграций **не переприменятся**. Чтобы пересоздать базу с нуля:

```bash
docker compose down -v      # удалить том с данными
docker compose up --build   # поднять заново
```

### Запуск без Docker (для разработки)

```bash
# backend (требуется локальный postgres + пользователь moon/moon)
cd backend
go run ./cmd/MoonCrisis

# frontend (в другом терминале)
cd frontend
npm install
npm run dev        # http://localhost:5173, proxy /api → localhost:8080
```

## Как реализованы требования

### 1. Тяжёлый заказ должен влиять на доставку

Тяжёлый груз замедляет ровер на пути **к заказу**: `скорость = база − weight/40`
(минус 1 клетка/день за каждые 40 кг, минимум 1). Обратно ровер едет пустым на
полной скорости.

Реализация: `service/deliveries.go` → `roverSpeed()`, `service/map.go` → `moveToward()`.

### 2. Ровер не везёт заказ, если не хватает батареи или грузоподъёмности

Перед назначением (`AssignRover`, `service/assign.go`) проверяются два условия:

- `заказ.Вес > ровер.Грузоподъёмность` → ошибка «превышена грузоподъёмность»;
- `расход_батареи_на_маршрут > ровер.Батарея` → ошибка «не хватает батареи на маршрут».

Батарея списывается **по факту пройденного пути** (за каждую клетку), а не вся сразу.

### 3. Разные зоны карты отличаются по риску/скорости

Зоны отличаются **по риску**: кратерное поле и горы дают заказы с повышенным риском
(риск заказа зависит от зоны при генерации), а плато — низкий риск. Бросок происходит
по честному риску заказа (виден в карточке заказа), без скрытых бонусов зоны.

### 4. Есть сценарий, где доставка невозможна

Стартовый ровер поднимает только **100 кг**, а заказы бывают до **150 кг**.
Значит заказ тяжелее 100 кг **нельзя отправить стартовым ровером** — нужен купленный
(в магазине, 500₽) с грузоподъёмностью **200 кг**. Возможна и невозможность «нет батареи»
на дальний тяжёлый маршрут.

### 5. После доставки меняются очки/деньги, батарея и статус заказа

При успешной доставке:
- **деньги** + награда заказа;
- **рейтинг** +5;
- **батарея** ровера уменьшается на реально пройденный путь;
- **статус заказа** → `completed` (ровер затем возвращается и становится свободным).

При провале/просрочке: статус заказа → `failed`/`expired`, штраф рейтинга
(−10 / −5 / −3 в зависимости от ситуации), батарея тоже списывается по пути.

### 6. Цель игры

- Продержаться **до 50-го дня** → **победа**: на экране итогов «вы заработали N монет».
- **Рейтинг ≤ 0** → поражение («рейтинг базы упал до нуля»).
- Основная метрика победы — сумма заработанных денег за партию.

### Влияние веса

Вес груза влияет на доставку тремя способами:

1. Скорость на пути к заказу. Замедление на 1 клетку за каждые 40 кг:
   `скорость = база - вес/40` (минимум 1). Обратно пустой ровер едет на полной скорости.

   Примеры для стартового ровера (скорость 5):
   - 40 кг -> 4 клетки в день
   - 80 кг -> 3 клетки в день
   - 120 кг -> 2 клетки в день
   - 150 кг -> 2 клетки в день (`150/40 = 3`, `5 - 3 = 2`)

2. Расход батареи на клетку: `2 + вес/100`.
   - при весе 40 кг -> 2.4 батареи на клетку
   - при весе 150 кг -> 3.5 батареи на клетку

   Тяжелый груз тратит батарею заметно сильнее.

3. Грузоподъемность. Заказ тяжелее грузоподъемности ровера вообще не назначается
   (ошибка "превышена грузоподъемность").

### Влияние риска и окружения (зоны)

Зоны карты влияют на сложность через риск заказов, которые в них генерируются:

| Зона | y | Риск зоны | Влияние |
| --- | --- | --- | --- |
| Кратерное поле | 0-3 | 40 | заказы здесь самые рискованные (5-12%) |
| Горы | 4-6 | 20 | средний риск |
| Плато (база) | 7-9 | 0 | минимальный риск |

Риск заказа = `5 + rand(0..19) * (риск зоны / 100)`. В кратерном поле риск выше,
чем на плато: туда выгодно, но опаснее.

Бросок при доставке: по прибытии ровера к точке проверяется `rand(0..99) < риск`.
Если не повезло - ровер ломается (breaking), заказ становится failed, рейтинг падает
на -10, ровер нужно чинить в магазине за 100.

Батарея списывается по факту пройденного пути (за каждую клетку), а не вся разом.
